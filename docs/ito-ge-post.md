# კომპანიის ყველა თანამშრომლისთვის Outlook-ის HTML ხელმოწერის შექმნა VBScript-ით

ერთიანი კორპორაციული ელფოსტის ხელმოწერა კომპანიის ვიზუალურ სტილს იცავს და თანამშრომლების საკონტაქტო მონაცემების სწორად ჩვენებას ამარტივებს. Windows domain გარემოში ამის ერთ-ერთი უფასო გზა არის VBScript, რომელიც თანამშრომლის ინფორმაციას Active Directory-დან იღებს, HTML ხელმოწერას ქმნის და Classic Outlook-ში ნაგულისხმევად აყენებს.

ამ მეთოდის მთავარი უპირატესობა ცენტრალიზებული შაბლონია: სახელი, პოზიცია, კომპანია, ელფოსტა და ტელეფონები ავტომატურად მოდის AD-დან, ხოლო საერთო მონაცემები — ლოგო, მისამართი, ვებსაიტი და ფერები — ადმინისტრატორს სკრიპტში ერთხელ აქვს განსაზღვრული.

## ვის გამოადგება

მეთოდი გამოსადეგია ორგანიზაციისთვის, რომელიც იყენებს:

- local Active Directory-ს;
- domain-joined Windows კომპიუტერებს;
- Classic Outlook for Windows-ს;
- Group Policy-ს მომხმარებლის logon script-ების გასავრცელებლად.

ეს გადაწყვეტა არ არის გათვლილი New Outlook-ზე, Outlook Web-ზე, macOS-ზე ან მობილურ მოწყობილობებზე. ასევე გასათვალისწინებელია, რომ Microsoft VBScript-ს ეტაპობრივად აუქმებს, ამიტომ მეთოდი უფრო legacy გარემოს პრაქტიკული გადაწყვეტაა.

## მუშაობის პრინციპი

მომხმარებლის Windows-ში შესვლისას GPO უშვებს VBS ფაილს. სკრიპტი `ADSystemInfo`-ით ადგენს მიმდინარე domain user-ს, LDAP-ით კითხულობს მის ატრიბუტებს და ქმნის HTML ფაილს მის პროფილში:

```text
%APPDATA%\Microsoft\Signatures
```

ამის შემდეგ Microsoft Word-ის COM ინტერფეისით შექმნილი ხელმოწერა აირჩევა როგორც ახალი წერილების, ასევე Reply/Forward წერილების ნაგულისხმევი signature.

## რომელი AD ველები გამოიყენება

| ხელმოწერაში | AD ატრიბუტი |
|---|---|
| სახელი და გვარი | displayName |
| პოზიცია | title |
| კომპანია | company |
| ელფოსტა | mail |
| სამუშაო ტელეფონი | telephoneNumber |
| მობილური | mobile |

თუ თანამშრომლებისთვის ეს ველები სწორად არ არის შევსებული, ხელმოწერაშიც ინფორმაცია ცარიელი ან არასწორი იქნება. ამიტომ rollout-მდე სასურველია AD მონაცემების აუდიტი.

## ტესტირება

სკრიპტი ჯერ ერთ სატესტო მომხმარებელზე უნდა გაეშვას:

```bat
cscript.exe //nologo create-outlook-signature.vbs
```

შემდეგ Classic Outlook-ში უნდა შემოწმდეს **File → Options → Mail → Signatures**. აუცილებელია სატესტო წერილის გაგზავნა შიდა და გარე მისამართებზე, რათა დადასტურდეს HTML განლაგება, ქართული სიმბოლოები, ბმულები და ლოგოს ჩატვირთვა.

## GPO-ით გავრცელება

Group Policy Management-ში გახსენით შესაბამისი GPO და გადადით:

**User Configuration → Policies → Windows Settings → Scripts (Logon/Logoff) → Logon**

აქ დაამატეთ VBS ფაილი. პოლიტიკა ჯერ სატესტო OU-ზე გამოიყენეთ, ხოლო წარმატებული შემოწმების შემდეგ — თანამშრომლების ძირითად OU-ებზე. შემდეგი sign-in-ისას ხელმოწერა თითოეული მომხმარებლის პროფილში ავტომატურად შეიქმნება.

## მნიშვნელოვანი შეზღუდვები და უსაფრთხოება
